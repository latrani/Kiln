## Global Constraints

- Relay log lines go through `internal/str/locales/en.toml`; commits touching locales end with a `Strings:` trailer.
- Tests build expected text from the catalog.
- New timing-sensitive tests are stress-run (`-race -count=40 -cpu 1`) and mutation-checked before pushing.
- Goldens are taken only on the current main look; nothing on the page changes in that PR.

## Decisions this plan makes

- **The caps:** waiting resume sockets per client bucket ≤ `max_per_ip`, and in all ≤ `max_conns`, counted separately from connection slots. A page resumes at most as many connections as it has held, and those are already capped by `max_per_ip`, so a real page never hits it. No new setting.
- **Refusals:** over the bucket cap, close with `CodeTooMany`; over the total, `CodeBusy`. Either is logged once per refusal with a new line, `relay.refused_resuming = "refused {ip}: too many resumes waiting to name a connection"`. The page's resume loop already retries.
- **The count ends** as soon as the first message is read (token checked, good or bad) or the wait times out.
- **Goldens:** taken on this Mac's Chrome (CI doesn't run smoke tests). `TestGoldenStable` passes and a second `TestGolden` run with no `-update` passes before committing.
