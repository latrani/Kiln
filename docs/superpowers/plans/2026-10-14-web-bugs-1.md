# Web bugs, batch 1 (#156, #153, #158, #159) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix four web bugs where someone gets stuck or loses something:
- **#156:** the editor stuck after a save or delete in flight.
- **#153:** accents, AltGr letters and IME input typed outside the input are lost.
- **#158:** log mode loses your place per character.
- **#159:** a refused copy says nothing.

**Architecture:** Each bug is its own task, small and local. Only #156 touches Go: its answers say which editor they're for. Everything else is the page. #162 (password managers) isn't here, since it needs trial and error in Safari with Indi.

**Tech Stack:** Go (internal/webapi), Preact + TypeScript (web/ui), node:test, headless Chrome smoke (web/smoke).

**Spec:** the issues themselves, plus `docs/superpowers/specs/2026-10-12-web-ui-design.md` (the web matches the TUI; browser-native beats mimicking).

## For you to check

1. **#156, a save that lands while its editor is away:**
   - **Saved** removes the parked or hidden editor; there's nothing left to save.
   - **Refused** keeps it, with Go's reasons showing when it comes back, and Save works again.
   - **A deleted world** takes its hidden and parked editors with it, as the open one's delete already does.
2. **#156, a settings read that fails** (Go can't read the world's file): Go already says why on the status line. Now the page also stops waiting, so an editor never pops open later out of nowhere.
3. **#153:** typing anywhere outside a control sends the key to the input. That now covers a dead key (Option+E on a Mac, then E for é), an AltGr letter, an Option letter (Option+A for å), and the start of an IME composition. Shortcuts still win: a key the page already used (Alt+T, Ctrl+L) isn't sent to the input.
4. **#158:** log mode keeps each character's place:
   - **Switching** away and back puts you where you were.
   - **Ctrl+L** to hide and show again puts you where you were.
   - **Esc and reopening** starts at the newest line, as the TUI does, since Esc closes log mode.
5. **#159:** when the browser refuses a copy, the status line says "the browser didn't allow the copy". That replaces Go's "copied N lines", which wasn't true. New string `web.copy_refused`.
6. **IME and dead keys in Safari** go on your hand-check list next to the IME Enter check. The smoke test covers Chrome only.

## Global Constraints

- **Strings come from the catalog,** with a `Strings:` trailer on the commit. Tests read the catalog.
- **The TUI's goldens never move.** This plan doesn't touch `internal/ui`.
- **Pre-1.0:** Go's `Saved` and `Problems` gain fields with no compatibility shim. The page and Go ship together.
- **No personal names.**

## Review Focus

1. **An answer that matches nothing** (an editor Esc'd away mid-save) changes nothing and throws nothing. → Task 2's tests.
2. **Two editors for the same target**, one open and one drafted: the answer settles the one that sent it, which is whichever has `pending` equal to its `Op`. → Task 2's tests.
3. **A shortcut with Alt or Ctrl** (Alt+T, Ctrl+L, Alt+↓) never ends up typed into the input. → Task 3's unit test, which uses `defaultPrevented` and non-printing keys.
4. **Log mode's place when the lines change while you're away** (older history loaded, the filter changed): the place comes back by line number, falling back as `topFor` does. → Task 4's smoke step.
5. **Copy with no `navigator.clipboard` at all** (an insecure context) says so too, instead of throwing. → Task 5's test.

```ts
// settleAway settles an editor that isn't open (parked, or kept as a
// draft) when Go answers what it sent: saved, it goes, with a deleted
// world's other drafts and parked editors; refused, it keeps Go's
// reasons for when it comes back.
function settleAway(s: State, a: Answer): State {
  const mine = (ed: Editor) => ed.pending === a.Op && targetKey(ed.target) === a.target;
  const fix = (ed: Editor): Editor | undefined => (!mine(ed) ? ed : a.Problems ? refuse(ed, a.Problems) : undefined);
  const keep = (m: Record<string, Editor>) =>
    Object.fromEntries(Object.entries(m).flatMap(([k, ed]) => {
      const f = fix(ed);
      return f ? [[k, f]] : [];
    }));
  s = { ...s, parked: keep(s.parked), drafts: keep(s.drafts) };
  if (a.Op === "delete_world" && !a.Problems) {
    const w = a.target.slice(1);
    const gone = (ed: Editor) => ed.target.kind !== "new_world" && ed.target.world === w;
    s = { ...s, parked: Object.fromEntries(Object.entries(s.parked).filter(([, d]) => !gone(d))), drafts: Object.fromEntries(Object.entries(s.drafts).filter(([, d]) => !gone(d))) };
  }
  return s;
}
```

```ts
// strayKey reports whether a key pressed outside any control belongs in
// the input: a printing key (with Option or AltGr too, which make
// letters), a dead key, or an IME starting. Not one the page already
// took (a shortcut), nor Ctrl or Cmd with a key, which are the browser's.
// The input is focused and the key isn't consumed, so the browser gives
// it, and what it composes, to the input.
export function strayKey(e: { key: string; keyCode?: number; isComposing?: boolean; ctrlKey: boolean; altKey: boolean; metaKey: boolean; defaultPrevented?: boolean }): boolean {
  if (e.defaultPrevented || e.metaKey) return false;
  if (e.isComposing || e.keyCode === 229 || e.key === "Process" || e.key === "Dead") return true;
  if ([...e.key].length !== 1) return false;
  return !e.ctrlKey || e.altKey; // Ctrl+Alt is AltGr in some browsers
}
```

```go
		many[i] = fmt.Sprintf("line %d", i)

	s := goldenScene(t, nil, func(s *scene) {
		kilntest.WriteLog(t, logstore.Layout{Root: s.logs, World: "fm", Char: "kit", CharName: "Kit"}, kilntest.LogDay, many...)
```
